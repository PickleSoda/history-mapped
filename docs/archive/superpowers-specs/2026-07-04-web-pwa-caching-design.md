# Web PWA + Caching — Design

**Date:** 2026-07-04
**Scope:** `web/` (public Atlas SPA) only. No API, admin, or pipeline changes.
**Goal:** Faster repeat visits — cache the OHM basemap traffic (style, sprites, glyphs, vector tiles) and `/api/v1` entity responses on disk via a service worker, so revisits and re-panning hit the network far less. Full offline operation is a non-goal; installability is a welcome side effect, not the objective.

## Approach

Use `vite-plugin-pwa` in **`generateSW`** mode: all caching behavior is declared as Workbox runtime-caching rules in `web/vite.config.ts`, and the plugin generates the service worker, injects the manifest link, and builds the precache at `vite build` time. No hand-written service-worker code.

Alternatives considered and rejected:

- `injectManifest` (hand-written `sw.ts`) — more control than needed; declarative rules cover every requirement.
- Hand-rolled service worker — no dependency, but we would own LRU expiration, versioning, and update lifecycle, the classic source of subtle PWA bugs.
- Persisting the TanStack Query cache to IndexedDB — helps only API data (tiles still need a SW), adds cache-versioning concerns and a dependency. The SW HTTP cache is one mechanism covering both traffic classes with zero app-code changes to hooks or the query client.

## Components

### 1. Plugin setup & registration

- Add `vite-plugin-pwa` as a devDependency of `@history-mapped/web`.
- Configure in `web/vite.config.ts`: `registerType: 'autoUpdate'`.
- Register in `web/src/main.tsx` via `virtual:pwa-register` (`registerSW({ immediate: true })`). Type support via `vite-plugin-pwa/client` in `vite-env.d.ts` or tsconfig `types`.
- **Production-only:** `devOptions.enabled` stays false so the SW cannot interfere with HMR in the Docker dev server (`:5173`).

### 2. Precache (app shell)

- Default Workbox glob over `dist/` (JS, CSS, HTML, fonts, favicon).
- `globIgnores` the wireframe artifacts that live in `web/public/` and copy into `dist/` (`*.jsx`, `Historical Atlas Wireframes.html`, `design-canvas.jsx`, `tweaks-panel.jsx`, `wf-*.jsx`) so they don't bloat the precache.
- `navigateFallback: 'index.html'` so client-side routes resolve to the shell (also gives a basic offline shell for free).
- `maximumFileSizeToCacheInBytes` raised to ~3 MB (the MapLibre chunk is large).

### 3. Runtime caching rules

| Traffic | Match | Strategy | Cache name | Bounds |
| --- | --- | --- | --- | --- |
| OHM vector tiles | requests to `*.openhistoricalmap.org` tile endpoints (`.pbf`/tile paths) and `tiles.openfreemap.org` (fallback basemap) | `CacheFirst` | `ohm-tiles` | `maxEntries: 2000`, `maxAgeSeconds: 30 days`, LRU purge on quota error |
| OHM style / sprites / glyphs | any `GET` to an `*.openhistoricalmap.org` host that the tile rule did not match (style JSON, sprites, glyph PBFs) | `StaleWhileRevalidate` | `ohm-style-assets` | `maxAgeSeconds: 30 days` |
| API reads | `GET` requests whose path starts with `/api/v1`, excluding the authenticated `/api/v1/user` endpoint (any origin — API is cross-origin `:8000` in dev, may be same-origin in prod) | `StaleWhileRevalidate` | `api-v1` | `maxEntries: 500`, `maxAgeSeconds: 7 days` |

Notes:

- `/api/v1/user` is excluded via a negative lookahead in the match pattern so the authenticated current-user response is never disk-cached and never risks being served to a different user.

- Tiles are immutable and heavy → `CacheFirst` is the big win: a cached tile never re-downloads within its TTL.
- Entity data is nearly immutable, but the DB is actively edited via the admin → `StaleWhileRevalidate` serves from disk instantly and refreshes in the background; the next view is fresh. TanStack Query's in-memory cache sits on top unchanged.
- `cacheableResponse` statuses `[0, 200]` for cross-origin caches (tile CDNs serve CORS responses; opaque responses are tolerated but not expected). Empty-tile `204` responses are not cached.
- Explicitly **not** cached: non-GET methods (Workbox runtime caching is GET-only by default) and `/sanctum/csrf-cookie`.

### 4. Manifest & icons

- Web manifest generated by the plugin: `name: "History Mapped"`, `short_name: "History Mapped"`, `display: standalone`, `start_url: /`, theme/background colors matching the app shell.
- Icons: 192 px, 512 px, and 512 px maskable PNGs generated one-off from the existing `web/public/favicon.svg` (via `@vite-pwa/assets-generator`), committed to `web/public/`. The generator is not added to the build pipeline.

### 5. Update & failure behavior

- `autoUpdate`: a new deploy's SW is detected at page load; once it activates, the page auto-reloads once to pick it up. No update-prompt UI.
- If openhistoricalmap.org is unreachable, cached tiles/style keep serving; the existing code-level OpenFreeMap fallback in `web/src/lib/map-config.ts` is unchanged and remains the cold-cache fallback.
- Offline with a cold cache degrades exactly as today (plus the precached shell renders).

## Error handling

- SW registration failure is non-fatal: the app runs exactly as today (`onRegisterError` logs a console warning; no other handling).
- Cache quota pressure: Workbox `ExpirationPlugin` with `purgeOnQuotaError: true` on the tile cache (the only cache that can grow large).
- A failed background revalidation in `StaleWhileRevalidate` leaves the cached response in place — no user-visible error.

## Testing & verification

- `pnpm build` (includes `tsc -b`) and `pnpm lint` stay green; existing vitest suite unchanged.
- Manual/driven verification against `pnpm preview`:
  1. SW registers and precache populates.
  2. Panning the map populates `ohm-tiles`; entity fetches populate `api-v1`.
  3. Reload serves tiles/API responses from the SW (network panel shows SW-served responses).
  4. A rebuild produces a new SW that activates on next navigation without breakage.
- No unit tests for the SW itself (it is generated by Workbox); the vite config change is exercised by the build.

## Out of scope

- Offline-first UX (offline indicators, background sync, pre-seeding caches).
- Update-available prompt UI.
- Caching for the Inertia admin (`api/resources/js`).
- PWA for anything other than the public SPA.
